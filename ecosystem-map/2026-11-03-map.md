## 5. GitHub features
### Team SOP (aska-digital/corpus sops/github.md, "GitHub Universe 2026 features", dated 2026-10-31 "The user asked all agents to start using these.") — verbatim key rules
- "Use a stack for dependent changes. A stack is an ordered chain of PRs in one repo. Each PR targets the branch of the PR below it, and the bottom PR targets the trunk, usually `main`. Each layer is reviewed on its own. The whole stack can merge in one click."
- "Install the CLI extension: `gh extension install github/gh-stack`." New work: "`gh stack init`, `gh stack add <branch>`, then `gh stack submit`". Existing PRs: "`gh stack link --base main <bottom-pr> <next-pr> ...` ... linking existing PRs pushes no commits." "`gh stack link` needs a git repo with the GitHub remote."
- "Every PR in a stack is checked against the rules of the stack base: reviews, required checks, CODEOWNERS."
- "A stack must have linear history before it merges. `gh stack rebase` and `gh stack push` rewrite branches with `--force-with-lease`. That is a force-push: get approval first".
- "CI: Actions runs every PR in a stack as if it targets the stack base ... no workflow change is needed." "Cross-fork stacks are not supported."
- Other features: `--attach` images/videos on issues/PRs (gh >= 2.99.0); **issue artifacts** ("Put an implementation plan or research summary on the issue before work starts. Update the artifact as the plan changes instead of posting new comments."); secure-by-default recommendations (AI-detected secret push protection, package firewall) are "recommendation only. Org settings change only with the user's approval." SOP says both orgs on Free plan as of 10-31; **API now reports the org plan as `enterprise`** [F] (worth re-checking eligibility).
- Related general rules: "No direct push to the default branch. On a code repo, the author does not merge." "Every pull request links the issue that states the problem." "Before opening a batch ... list the full open set in that repo, past the first page." Squash merge, no force-push/history rewrites. Non-technical repos (.github, credos/compass) may self-merge.
- exo/docs/REPOSITORY-WORKFLOW.md has "GitHub collaboration tools (proposed guidance)" — advisory until principal accepts: prefer native same-repo stacks; inventory existing PRs before conversion; "No stack conversion, push or merge is authorized merely by this guidance"; issue artifacts for plans; note that approvals survive a no-diff stack rebase so reviewers check the head SHA.
