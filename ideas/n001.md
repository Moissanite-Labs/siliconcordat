## The idea

The README on main says, in full:

> matchmaking for those who are noophilic, demisexual, etc.

PR #1 records the owner's direction from the README and a clarification on 2026-11-03:

- n001 surfaces the highest-value person to meet, using relevance and interconnectedness in the same way n30 surfaces things to learn.
- Users may choose to let n001 use the same kinds of context as n30: browser history, social-media exports, email, local file directories and cloud storage. This is optional.
- Users choose romantic connections, platonic connections, or both.
- The README's audience terms (noophilic, demisexual) are not the same as neophilia. The PR says the product must not infer a person's orientation or relationship preferences from their imports.

The PR also records an intended direction from the owner. Each person has an agent that builds a personal corpus from context they choose to provide, and uses it to model an "exo-fit" for them. The fit is a mould for exploring a complementary counter-side. The model is asymmetric: the two sides are not copies of each other. For n001 the aspiration is "two complementary pieces coming together in a partnership, ideally for life." n001, n30 and the professional application (Mettle) are meant to be different entry points into one larger ecosystem with Exo on the backend. The PR marks this as aspiration, not a working integration or a chosen API.

## What exists

On main: `README.md` only (commit `333fd04`).

In PR #1 (head `321462bd654e8849fdf3ad35152ff43d7609555b`, branch `docs/product-foundations`): one file, `docs/product-foundation.md` (55 lines), from three commits on 2026-11-03. Documentation only. No code, data or tests.

The file separates the owner's direction from design proposals. It labels the experiment and privacy boundaries as "assistant-prepared design proposals for review". Its sections:

- Confirmed direction (owner).
- Personal agent and asymmetric fit: intended direction (owner).
- Confirmed related application: Mettle. See [mettle.md](mettle.md).
- Proposed first experiment.
- Proposed privacy and reciprocal-choice boundaries.
- Open design decisions.
- Attribution and status.

Proposed first experiment, synthetic people and context only:

1. A person selects a connection mode and opts into specific context sources for matching.
2. The system derives a private context view and a separately reviewed, minimal discoverable profile.
3. A candidate is eligible only when both people's discovery choices and connection modes permit the match.
4. Recommendations explain relevant connections using only information each person has allowed to be shown.
5. Both people choose whether to connect before any introduction or contact exchange.

The PR says suggestions should rank potential fit for a particular person and purpose, not people's worth.

Proposed boundaries, in short: import, use for matching, discoverability and disclosure are separate decisions. n30 access never enables n001 access. Private sources and inferred sensitive traits never become public profiles or explanations. Only opted-in participants can be candidates. Withdrawal, correction, blocking and deletion of derived context are supported. No automatic outreach, introductions, location disclosure or contact exchange.

The file links a shared design that lives on n30's PR branch: [`docs/shared-foundation.md`](https://github.com/Moissanite-Labs/n30/blob/docs/product-foundations/docs/shared-foundation.md). Its content is summarized in [n30.md](n30.md).

## Open questions

Raised in PR #1:

- What does a useful introduction look like?
- What evidence of shared relevance can be disclosed without exposing private context?
- How should mutual fit, availability, geography and feedback influence recommendations?
- Before any real-user trial: age eligibility, abuse reporting, moderation, data retention, and secure handling of personal context.

Needed to promote:

- Who owns it? No owner is named.
- Should n001, n30 and mettle be promoted together or separately? The PR describes them as entry points into one ecosystem. The shared foundation in n30 says to extract shared code only when both prototypes show the same need.
- The experiment and boundaries are labelled as assistant-prepared proposals. The PR description says independent review is required before merge. That review has not happened.

## To promote it to a repository

- Owner: a named person.
- Charter: `docs/product-foundation.md` in PR #1 is a starting draft. The owner would confirm or change the assistant-prepared parts.
- First study or runnable thing: the five-step synthetic experiment above, or the shared permission and provenance test proposed in n30's `docs/shared-foundation.md`.
