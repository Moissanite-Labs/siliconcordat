# mettle

- Status: idea
- Origin: [Moissanite-Labs/mettle](https://github.com/Moissanite-Labs/mettle) (to be archived). README added 2026-11-03. No pull requests.
- Related: [n001](n001.md) and [n30](n30.md). The README names both.

## The idea

The README on main says, in full:

> n001+n30

The repository holds nothing else. The only description of Mettle is in n001 PR #1 ([`docs/product-foundation.md`](https://github.com/Moissanite-Labs/n001/blob/321462bd654e8849fdf3ad35152ff43d7609555b/docs/product-foundation.md), commit `321462b`, 2026-11-03), under "Confirmed related application":

> The owner also wants a distinct fork/application for discovering valuable positions, employment, and contracts for individuals, and candidates for employers or recruiters. The owner names this application Mettle. Its intended complementary sides are the hiring organization's purpose, environment, and culture, and the individual's ikigai.

The same section says this is "an aspirational framing to evaluate with participants, not an implemented assessment or a validated predictor of employment outcomes." It also says the professional context is separate: it is "not permission to repurpose romantic or platonic profiles, source grants, or feedback for recruiting."

n001's PR places Mettle with n001 and n30 as entry points into one larger ecosystem with Exo on the backend. See [n001.md](n001.md).

## What exists

On main: `README.md` only (commit `0232e20`), one line. No other branches. No pull requests.

Related text elsewhere:

- n001 PR #1, `docs/product-foundation.md`, "Confirmed related application". Quoted above. It adds a proposed boundary:
  - Use only explicitly approved professional information.
  - Do not infer or use sensitive personal traits for hiring eligibility, selection, exclusion or ranking.
  - Keep consequential employment decisions with people. Do not automatically reject applicants or contact candidates.
  - Define candidate participation, employer access, visibility and consent separately before building a real-user workflow.
- n30 PR #1, `docs/shared-foundation.md`, "Future professional application". It says the application may reuse the permission and provenance concepts, but needs separate professional-purpose grants and candidate-approved information. It says "No new repository, name, or implementation has been selected." That text predates n001's naming of Mettle by about ten minutes.

## Open questions

Raised in the n001 and n30 PRs:

- How are candidate participation, employer access, visibility and consent defined? These must be settled before a real-user workflow.
- Does the purpose, culture and ikigai framing hold up with participants? The n001 PR says it is to be evaluated, not assumed.

Needed to promote:

- Who owns it? No owner is named.
- The README says only "n001+n30". Does Mettle mean only the professional application described in n001's PR, or something more? No source says more.
- n30's PR says no name has been selected; n001's PR names it Mettle. The records should agree.

## To promote it to a repository

- Owner: a named person.
- Charter: none exists. A charter could start from n001's "Confirmed related application" section and n30's "Future professional application" section.
- First study or runnable thing: none has been proposed. n30's PR says the permission and provenance concepts may be reused with professional-purpose grants. A study would need to be written first.
